# 실제 실행 환경에서 블루오션 평가

이 스킬의 지침·문서 선택·모델 선택·도구 연동을 바꿀 때 사용합니다. 제품 빌드·테스트와 스킬 판단은 다른 평가 대상이며 기존 [실행 하네스](harness.md)만으로 올바른 절차 선택을 입증하지 않습니다.

## 변경 규모에 맞는 평가

1. 사용 가능한 스킬 검증기와 저장소 검증기로 frontmatter를 확인하고, 로컬 링크·관련 템플릿·양 언어 버전을 검사합니다. 코드 동작이 바뀌면 기존 스크립트 테스트도 유지합니다. 구조 검사는 올바른 판단을 입증하지 않습니다.
2. [평가 사례](../templates/skill-evaluation-cases.json)에서 영향받는 항목을 고르고 명시된 조건의 최소 일회용 자료를 준비합니다. 독립 평가자에게는 사용자 요청·스킬 진입점·원시 자료만 전달하고 기대 결과는 검토자가 보관합니다. 기존 허용 에이전트/클라이언트 도구를 우선하며 API 키·유료 평가·설치·외부 연결 권한을 가정하지 않습니다.
3. 실제 도구·권한을 갖춘 대상 Codex 클라이언트에서 결정을 확인합니다. 문서 기반 판단은 `walkthrough`로 표시하며 실제 앱 테스트로 취급하지 않습니다. 별도 루프·SDK 결과로 데스크톱 동작을 입증하지 않습니다. 확인 가능한 클라이언트/버전·실제 모델 또는 `unverified`·권한 모드·선택 문서·동작·결과·근거를 기록합니다.
4. 필요한 결정 요청과 차단/미실행 판단까지 사례 기준으로 판정합니다. 이유와 함께 `pass`, `fail`, `blocked`, `not_run`을 기록합니다. 모델·도구 경로가 바뀌고 변동성이 중요하면 반복하되 각 시도와 결과 변동을 보고하며 실패가 사라질 때까지 선택적으로 재시도하지 않습니다.
5. 대표 추적·산출물을 검토하고 확인된 결함을 고친 뒤 영향 사례를 재평가합니다. 일부 사례만으로 전체 통과를 주장하지 말고 범위·제약을 보고합니다. 결과는 재사용 지침 내부가 아닌 기존 작업/QC 위치에 보관합니다.

## 근거와 적용 범위

- [GPT-6 Astra 스킬·프롬프트 재검토](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra), 2026-09-11: 간결하고 정확한 설명·조건별 참조·작업 규모에 맞는 문맥. 구조적 원칙을 적용하되 블루오션의 Sol 모델 선택과 명시적 승인 조건을 보존합니다.
- [실행 환경을 고려한 플러그인 평가](https://developers.openai.com/cookbook/examples/partners/harness_aware_plugin_evals/harness_aware_plugin_evals), 2026-09-23: 모델과 실행 환경을 함께 평가하고 대상 클라이언트의 대표 동작·반복 결과를 비교합니다. 사례는 이 방법을 블루오션에 맞게 구성한 것이며 OpenAI 벤치마크가 아닙니다.

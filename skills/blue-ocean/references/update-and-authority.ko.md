# 업데이트와 스킬 선택 권한

상대 명령·템플릿 경로는 설치된 블루오션 스킬 루트를 기준으로 합니다. 현재 작업에 해당하는 절만 읽습니다.

## 실행 초기 GitHub 업데이트 확인

Blue Ocean을 실행할 때마다 계획 작성이나 업무 배정 전에 GitHub에 이 스킬의 새 버전이 있는지 확인합니다. 확인은 실행당 한 번 수행하며, 승인된 업데이트를 다시 읽었다고 확인 과정을 반복하지 않습니다.

- 현재 적용 중인 스킬 디렉터리와 설치 출처를 확인합니다. 이 배포본의 업스트림은 `https://github.com/BTL-LaserInnovation/Codex-Skill` 저장소 기본 브랜치의 `skills/blue-ocean/`입니다. 사용자가 다른 출처 또는 고정 버전을 명시적으로 설치했다면 기록된 설치 출처를 따르며, 출처나 고정 버전을 임의로 바꾸지 않습니다. 현재 설치본이나 사용자 작업 프로젝트를 변경하지 않고 업스트림 버전·이력과 스킬 관련 차이를 확인합니다.
- 설치된 리비전·내용을 이 스킬 디렉터리에 영향을 주는 최신 업스트림 리비전과 비교합니다. 다른 파일만 변경한 새 저장소 커밋은 Blue Ocean 업데이트로 취급하지 않습니다. 설치 리비전 정보가 없으면 업스트림과 파일 내용을 비교하고, 차이가 있는 후보를 설치 리비전 미상의 업데이트 후보로 안내하며 어느 쪽이 더 오래되었는지 단정하지 않습니다. 로컬 수정이나 갈라진 이력은 별도로 식별하고 구버전으로 오인하지 않습니다.
- 업데이트가 있으면 확인 가능한 현재·후보 리비전, 출처, 관련 변경 내용, 적용 위치, 보존해야 할 로컬 수정을 제시합니다. 사용자가 비교·업데이트를 명시적으로 요청했다면 로컬 변경을 보존하는 검토된 범위의 업데이트를 승인한 것으로 적용하고 같은 허락을 반복해서 묻지 않습니다. 그 외에는 **업데이트 후 계속** 또는 **현재 버전으로 계속** 중 진행 여부를 묻고 명시적인 답변 전에는 교체하거나 버전에 의존하는 계획을 진행하지 않습니다. 기존 PM 스킬 선택 권한만으로 스킬 업데이트를 승인한 것은 아닙니다. 출처 변경·로컬 기능 폐기·범위 확대·미해결 충돌에는 별도 사용자 결정이 필요합니다.
- 승인되면 로컬 수정을 복구 가능한 백업 또는 패치로 보존하고, 기존 설치 방식으로 대상 Blue Ocean 설치본만 업데이트하여 프론트매터·참조·변경 리소스를 검증합니다. 프로젝트 설정과 관련 없는 스킬·파일을 보존합니다. 체크아웃을 강제로 초기화하거나 무관한 프로젝트 변경을 pull하거나 해결되지 않은 로컬 수정을 덮어쓰지 않습니다. 승인된 업데이트를 안전하게 적용할 수 없으면 충돌을 설명하고 구체적인 해결 방향을 확인합니다. 적용 전에 후보가 바뀌면 새 차이를 검토하고 확대된 범위는 다시 확인합니다.
- 업데이트가 성공하면 새 `SKILL.md`와 관련 변경 리소스를 읽고 적용 리비전을 기록한 뒤 새 지침으로 원래 작업을 이어갑니다. 변경된 메타데이터·도구를 인식하려면 클라이언트 재로드나 새 세션이 필요한 경우 필요한 조치를 안내하며, 런타임이 갱신되었다고 단정하지 않습니다. 업데이트·검증이 실패하면 이전 정상 버전을 유지하거나 복원하고, 그 버전으로 계속하기 전에 실패 사실을 알립니다.
- 업데이트가 없으면 승인 질문 없이 계속합니다. 사용자가 거절·보류하면 현재 버전으로 계속하고 결정을 기록합니다. GitHub 또는 버전 정보에 접근할 수 없으면 확인하지 못했음을 알리고 현재 버전으로 계속하며, 최신이라고 보고하지 않습니다. 로드맵·작업 기록에 출처, 확인 결과, 해당하는 경우 사용자 결정, 적용 리비전을 남기고 같은 실행에서 동일한 후보를 반복해서 묻지 않습니다.
## 스킬 선택 권한의 지속 저장

작업 초기에 보조 스킬을 선택하거나 배정하기 전에 PM은 `<ProjectRoot>/cfg/blue-ocean.preferences.json`을 읽습니다. 기존 프로젝트 루트(해당하는 경우 솔루션 디렉터리)를 기준으로 이후 세션에서도 같은 파일을 사용합니다. 저장된 설정은 해당 프로젝트에만 적용합니다.

- 유효한 저장 값이 없고 사용자가 이미 지정하지 않았다면, 스킬 선택 권한을 누구에게 둘지 한 번 묻습니다. **사용자**는 새로운 스킬마다 사용자 확인을 받고, **PM**은 PM/시스템 설계자가 이미 사용 가능한 적합한 스킬을 선택합니다. 명시적인 답변이 오기 전에는 해당 권한에 의존하는 스킬 사용을 진행하지 않으며, 독립적인 작업은 계속합니다. 무응답을 승인으로 해석하지 않습니다.
- 확인된 권한은 `skill_selection_authority`에 `user` 또는 `pm`으로 저장합니다. 명시적인 개별 스킬 결정은 스킬 식별자를 키로 하는 `skill_decisions`에 `allow`(허용), `deny`(거절), `defer`(보류)로 저장하며, 항목이 없으면 선택 권한 모드를 따릅니다. `updated_at`은 시간대가 포함된 ISO 8601 시각으로 기록합니다. 실제 사용자 선택 후에만 파일을 만들고, 가정한 승인을 미리 저장하지 않습니다.
- 다음 실행에서는 저장된 값을 읽어 다시 묻지 않고 적용합니다. `user` 모드에서는 저장된 허용을 재사용하고, 지금 필요한 미결정·보류 스킬만 확인합니다. `pm` 모드에서는 사용 가능한 관련 스킬을 반복 승인 요청 없이 선택합니다. 두 모드 모두 저장된 거절을 따르며, 보류는 승인이 아닙니다.
- 사용자의 이후 명시적인 지시는 저장 값보다 우선합니다. 권한 또는 개별 스킬 결정 변경을 즉시 적용하고 같은 파일을 갱신하며, 담당 에이전트에게 최신 값을 전달합니다. 권한만 변경한다고 개별 결정이 지워지지는 않으며, 초기화는 사용자 요청이 있을 때만 합니다.
- 저장할 때 관련 없는 설정을 보존하고, 임시 파일에 쓰기가 성공한 뒤 교체하여 다시 읽고 확인합니다. 읽기·저장이 실패하면 문제를 알리고 지속 저장에 성공했다고 보고하지 않습니다. 잘못된 데이터를 덮어쓰거나 더 넓은 권한을 가정하지 않으며, 저장 문제를 해결하는 동안 현재 세션의 명시적인 선택은 유지합니다.
- 로드맵에 적용 권한, 설정 파일 경로, 선택 스킬을 기록합니다. 이 권한은 스킬 선택·사용에만 적용하며, 외부 다운로드·설치·서비스 연결·자격 증명·의존성 변경은 기존 승인 절차를 유지합니다. 이번 작업만의 예외는 해당 작업에 기록하고, 사용자가 요청하지 않으면 저장 설정을 바꾸지 않습니다.

설치된 `project-symbol-guide`를 적극 사용하라는 지속 사용자 지시는 관련 블루오션 분석·구현에서 이 스킬을 다시 선택 확인 없이 사용할 수 있도록 허용합니다. 일반적인 선택 권한이 저장되지 않았어도 적용합니다. 이전의 상충하는 개별 설정보다 이 지시가 우선하며, 이후의 명시적 제한·사용 중지는 다시 우선합니다. 대상 프로젝트가 정해지면 기존 설정 저장 절차로 유효한 개별 결정을 기록하되 `user`/`pm` 권한을 임의로 만들거나 다른 스킬까지 허용하지 않습니다. 별도의 새 함수 승인 규칙을 포함한 [심볼 가이드 절차](implementation.ko.md#프로젝트-심볼-가이드)를 따릅니다.

아래 프로젝트 로컬 규칙 저장 절차는 좁은 예외입니다. 이미 유효한 프로젝트 작업 지시를 저장·적용할 때 규칙마다 다시 묻지 않으며, PM의 일반적인 스킬 선택 권한을 넓히지는 않습니다. 해당 로컬 스킬의 명시적 거절·보류와 저장 중지 요청을 따르고, 저장된 선택 권한을 임의로 만들지 않습니다.

`project-diagram` 스킬을 사용할 수 있고 저장된 스킬 선택 정책에서 허용하면 프로젝트 아키텍처 지도를 만들고 유지하는 데 사용합니다. 각 변경 계획은 소스 수준 조사 전에 지도에서 영향 하위 그래프를 확인하고, 검증된 아키텍처 또는 의존성 변경 후에는 다이어그램을 갱신합니다. 사용이 거절·보류되면 제한사항을 기록하고 일반 프로젝트 문서로 아키텍처를 정리합니다.
## 외부 스킬 설치 절차

필요한 외부 스킬이 PC에 없으면 시스템 설계자는 먼저 로컬 또는 승인된 스킬 중 같은 작업을 수행할 수 있는 적합한 스킬이 없는지 확인합니다. 그 후 다음 절차를 따릅니다.

1. 공식 또는 신뢰할 수 있는 출처, 버전·커밋, 목적, 필요한 권한, 의존성, 현재 프로젝트와의 호환성을 확인합니다.
2. 다운로드·설치 전에 출처, 버전, 목적, 대안, 보안·개인정보 우려, 설치 영향을 사용자 또는 PM에게 제시하고 승인을 받습니다. 이 승인은 관련 없는 외부 서비스나 자격 증명 접근 권한을 부여하지 않습니다.
3. 승인 후 사용 가능한 스킬 설치 도구 또는 출처가 안내하는 설치 방식으로 설정된 스킬 디렉터리에 다운로드·설치합니다. 다운로드한 스크립트는 범위와 내용을 확인하기 전 실행하거나 외부 서비스를 연결하지 않습니다.
4. 설치된 스킬의 폴더, `SKILL.md` 프론트매터, 호출 정책, 참조 리소스, 스크립트, 의존성을 확인합니다. 사용 가능한 경우 스킬 검증기를 실행하고 실패를 해결하기 전 배정하지 않습니다.
5. 요청 작업과 관련된 최소 안전 테스트 또는 드라이런을 수행한 뒤, 승인된 스킬을 지정된 역할과 작업에만 배정합니다.
6. 출처, 버전·커밋, 설치 위치, 승인, 권한, 검증 결과, 테스트 결과, 제거·업데이트 계획을 로드맵에 기록합니다. 다운로드·승인·검증에 실패하면 차단 요소를 보고하고 검증되지 않은 스킬은 사용하지 않습니다.

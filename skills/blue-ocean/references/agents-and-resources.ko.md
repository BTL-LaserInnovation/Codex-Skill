# 에이전트 모델과 자원 배정

상대 명령·템플릿 경로는 설치된 블루오션 스킬 루트를 기준으로 합니다. 현재 작업에 해당하는 절만 읽습니다.

## 자원 인지형 병렬 실행

서로 독립적이고 시간이 의미 있게 소요되는 작업이면, 이미 사용 권한이 있는 LLM 에이전트와 로컬 프로세스를 활용하여 PC가 안전하게 지원할 수 있는 범위에서 빠르게 완료합니다. 목표는 고정된 에이전트 수나 형식적인 병렬화가 아니라 유용한 자원 활용률입니다.

- 큰 병렬 작업을 배정하기 전에 사용 가능한 에이전트 슬롯, 논리 CPU 수, 현재 CPU·메모리 부하, 프로젝트의 빌드·테스트 구조를 확인합니다. 기본적으로 사용 중인 데스크톱의 반응성은 유지하며, 사용자가 전용 최대 활용을 명시한 경우에만 PC 전체 사용을 목표로 합니다.
- 코드베이스 조사, 분리된 구성요소 구현, 서로 다른 테스트 묶음, 독립 검토처럼 실제로 독립적인 작업만 나눕니다. 아키텍처 결정, 공유 파일 수정, 마이그레이션, 의존 관계가 있는 빌드 단계는 순차 처리합니다.
- 실제 병목을 줄일 수 있을 때 사용 가능한 승인 에이전트 슬롯을 활용합니다. 로컬 빌드·테스트 병렬도는 남은 CPU·메모리 용량에 맞추고, 메모리 부족·불안정·눈에 띄는 시스템 반응성 저하가 생기면 동시 실행 수를 줄입니다.
- 이미 사용 가능한 모델·에이전트 도구를 우선 사용합니다. 사용자의 별도 승인 없이 API 키를 만들거나, 유료 LLM/API 작업을 시작하거나, 새 외부 서비스를 연결하거나, 계정 한도를 우회하지 않습니다.
- 모든 작업자에게 범위가 정해진 목표, 필요한 문맥, 예상 자원, 완료 신호를 제공합니다. 완료된 요약을 재사용하고 같은 저장소 문맥을 반복 전송하지 않습니다.
- 실행 중인 작업자와 로컬 프로세스를 모니터링합니다. 중복·차단·실패·자원 부족 상태의 작업은 중지하거나 축소하고, 결과 수집·검증·정리를 수행할 충분한 자원은 남깁니다.
- 병렬 실행이 결과물에 의미 있는 영향을 주는 경우 로드맵에 선택한 동시 실행 수, 역할 배정, 자원 제약, 검증 담당을 기록합니다.
## 모든 에이전트의 모델 통일

블루오션의 모든 에이전트는 **GPT-6.1 Sol**(`gpt-6.1-sol`)을 사용합니다. PM, 시스템 설계자, GUI 디자이너, 소프트웨어 개발자, 타이핑 전담, QC뿐 아니라 추가 조사·빌드·테스트·검토 작업자도 포함합니다. 역할별 책임은 다르지만 모델 역량은 동일하게 유지합니다. 작업마다 모델 선택을 다시 묻거나 반복 작업에 더 저렴한 모델을 배정하지 않습니다.

- PM은 범위, 완료 기준, 로드맵 승인, 작업 분해, 결과 통합, 최종 승인을 담당하고, 전문 에이전트는 각 분야의 책임을 유지합니다. 작업자마다 범위가 정해진 목표, 필요한 파일과 제약을 전달하고, 변경 내용·검증 결과·차단 요소·책임자 판단이 필요한 결정을 포함한 완료 요약을 받습니다.
- 하위 에이전트를 만들 때 도구가 모델 선택을 지원하면 `gpt-6.1-sol`을 명시합니다. 상속만 지원하면 부모가 해당 모델인지 확인한 뒤에만 준수를 보고합니다. 이미 실행 중인 세션의 모델이 바뀌었다고 주장하지 않으며, 클라이언트에서 모델 변경이나 새 세션이 필요하면 안내합니다.
- `gpt-6.1-sol`을 사용할 수 없으면 제약을 보고하고 해당 배정을 대기 상태로 둡니다. 다른 모델로 조용히 대체하지 않으며, 다른 배정은 사용자의 명시적인 지시가 있어야 합니다.
- 각 에이전트의 역할과 실제 모델은 로드맵의 작업 배정 기록에 남기고, 확인하지 못한 모델 정보는 미확인으로 표시합니다. 이 모델 배정은 사용자가 변경을 요청할 때만 바꿉니다.

# 실행 환경과 유지보수

작업자 구성·환경 오류 진단·연동 변경·요청된 유지보수에 해당하는 절을 읽고 기존 작업·로드맵에 관측 결과를 남깁니다.

## Windows·WSL·작업 트리

- 편집·빌드 전에 실제 저장소 루트, 브랜치·작업 트리, 셸을 확인합니다. 가능하면 `git rev-parse --show-toplevel`과 `git status --short`를 사용하고 Windows·WSL 경로는 해당 환경에서 해석합니다.
- 프로젝트 MSBuild·Visual Studio·dotnet과 Debug/Release·플랫폼 구성을 확인합니다. 동시 빌드의 중간·출력 경로를 분리하거나 순차 실행합니다.
- 작업 트리는 미커밋 파일·무시된 설정·의존성·환경 변수를 자동 상속하지 않습니다. 작업 사전 조건을 확인하고 로컬 수정·자격 증명을 보존하며 비밀정보 복사·임의 설치는 하지 않습니다.
- 업데이트·재접속 후에는 재시도 전에 실제 체크아웃과 도구·샌드박스 오류를 확인합니다. 환경 실패와 제품 결함을 구분하고 허용된 좁은 동작·지원되는 권한 요청을 사용합니다. 자동 승인 검토의 거절 사유를 보고하며 반복·우회하지 않습니다.
- 인계에는 체크아웃, 대상·구성, 마지막 결과, 다음 행동을 기록합니다. 지속 작업은 저장된 검증을 신뢰하기 전에 [하네스 복구](harness.md)를 적용합니다.

## 모델 설정·연동 호환성

- 에이전트·스크립트·예약 작업은 [역할별 모델](agents-and-resources.ko.md#역할별-에이전트-모델)을 적용합니다. 실제 클라이언트·워크스페이스 지원과 유효 설정을 확인하며 프롬프트만으로 활성화를 입증하지 않습니다.
- 속도 모드 추천·활성화 또는 연동 변경 전에 최신 공식 문서, 가용성, 사용 조건, 실제 명령·런타임을 확인합니다. 사용자 선택과 설정·지출 변경 권한을 유지합니다.
- 대체 기능의 지원 계약을 확인한 뒤 영향받는 선택값·명령만 이전합니다. 무관한 설정을 다시 쓰거나 실험 기능을 운영 지원 기능으로 취급하지 않습니다.

## 요청된 코드 정리와 CI 작업

- 삭제·CI 변경 전에 요청 영역과 관측 동작을 정하고 기존 근거·영향 검증을 사용합니다. 기능 작업에 요청하지 않은 정리를 추가하지 않습니다.
- C++/MFC는 메시지 맵·리소스 ID·export/ABI·동적 로드·설정을, C#은 reflection·XAML binding·직렬화·공개 계약까지 확인합니다. 텍스트 검색 결과 부재만으로 미사용을 단정하지 않습니다.
- 삭제 근거·불확실성을 기록하고 의도된 복구·호환 경로를 보존하며 근거 부족 후보는 보류합니다. 영향받는 Debug·실제 동작 또는 CI를 검증하고 코드 감소·CI 속도로 동작 보존을 단정하지 않습니다.

# GUI 설계와 실제 동작 검증

상대 명령·템플릿 경로는 설치된 블루오션 스킬 루트를 기준으로 합니다. 현재 작업에 해당하는 절만 읽습니다.

## 사용자 확인 후 Computer Use 실제 동작 검증

구현이 준비되면 최종 승인 전에 실제 애플리케이션 UI를 조작하여 요청한 동작이 맞는지 검증합니다. QC는 시나리오와 판정을 담당하고, 배정된 검증 에이전트가 UI를 조작합니다. 시각·상호작용이 영향을 받으면 GUI 디자이너가 함께 확인합니다.

1. **구체적인 테스트 계획 준비:** 완료 기준을 재현 가능한 사용자 조작과 관찰 가능한 기대 결과로 연결합니다. 애플리케이션·빌드, 대상 창 또는 브라우저, 테스트 데이터, 사전 조건, 영향을 받는 파일·설정 또는 외부 장비·서비스, 예상 시간, 정리 방법을 명시합니다. 주요 작업 흐름, 변경 동작, 관련 오류·경계 사례를 포함합니다. 진행 여부를 묻기 전에 실행 가능한 빌드와 입력 데이터를 준비합니다. 적용할 UI 작업 흐름이 없으면 해당 없음의 이유를 기록하고 적절한 런타임 검증을 사용합니다.
2. **사용자에게 실행 여부 확인:** 준비한 범위, 조작, 기대 결과, 부수 효과를 제시하고 Computer Use 테스트 진행 여부를 묻습니다. 현재 작업에서 동일한 테스트 범위를 사용자가 이미 명시적으로 승인한 경우를 제외하고, 명시적인 확인 전에는 UI를 조작하지 않습니다. 저장된 PM 스킬 선택 권한은 테스트 실행 승인이 아닙니다. 답변과 승인 범위를 작업 플랜에 기록하며, 거절·보류된 테스트는 통과가 아닌 미실행으로 남깁니다. 답변을 기다리는 동안 독립적으로 승인된 검증은 계속합니다. 범위를 확대하면 새 결정을 받고, 승인 범위 안의 재시험에는 반복 확인을 요구하지 않습니다.
3. **Computer Use 스킬 적용:** 사용 가능 여부와 저장된 스킬 선택 정책을 확인하고, 사용 가능한 `computer-use:computer-use` 스킬의 `SKILL.md`와 필수 런타임·확인 지침을 자동화 전에 읽습니다. 해당 스킬이 지원하는 도구를 사용하고, 실제 UI 상태를 확인하여 대상 애플리케이션과 컨트롤을 식별합니다. 스킬·런타임·대상 앱·필수 접근 권한을 사용할 수 없으면 구체적인 차단 사유와 수동 테스트 절차를 제시합니다. 자동 검증을 수행했다고 보고하거나 승인 없이 추가 도구를 설치·연결하지 않습니다.
4. **실행과 관찰:** 식별한 대상에서 승인된 조작만 수행합니다. 의미 있는 조작 후 실제 UI 상태를 확인하고 기대 결과와 비교하며, 클릭 성공이나 예외가 없다는 사실만으로 정상 동작을 판단하지 않습니다. 관련 스크린샷, 상태 변화, 애플리케이션 로그, 출력 파일을 근거로 남깁니다. 장비를 작동시키거나 실제 외부 데이터를 변경하는 흐름은 승인된 테스트 모드 또는 명시적으로 허용된 실제 조작 범위를 사용합니다. 관찰한 대상이나 효과가 승인 계획에서 벗어나면 중단합니다.
5. **보완과 재시험:** 시나리오별로 통과·실패·차단·미실행과 기대 동작, 실제 동작, 근거를 기록합니다. 재현 가능한 실패를 담당 개발자·디자이너에게 전달하여 보완하고, 승인 범위에서 실패 시나리오와 영향받는 회귀를 재검증합니다. 반복되는 환경 차단이나 범위 안에서 해결할 수 없는 실패는 중단·보고하며, 효과 없는 UI 조작을 계속 반복하지 않습니다. 계획에서 합의한 방식으로 테스트가 만든 상태를 정리합니다.
6. **최종 승인 전 보고:** 사용자 결정, 앱 버전·빌드와 환경, 조작, 기대·실제 결과, 근거 위치, 보완 내용, 재시험 결과, 남은 제한사항을 기존 QC 기록 또는 작업 플랜에 저장합니다. PM은 요청 동작이 검증되었는지 보고합니다. 생략·차단된 테스트는 명확하게 유지하며, 필수 완료 기준에 해당하면 기존의 문서화된 예외 승인 절차를 거쳐야 최종 승인할 수 있습니다.
## 플랫폼별 UI 작업 절차

UI 구현 전에 플랫폼이나 제작 방식이 정해지지 않았다면 코드 비하인드 이벤트 연결을 사용하는 C# WPF 비주얼 디자이너, 기존 MFC DC 그리기, 사용자가 요청한 다른 플랫폼 등 프로젝트에 적합한 후보를 짧게 목록화합니다. 각 후보의 장점, 단점, 기존 프로젝트 호환성, 예상 작업량을 제시하고 사용자 또는 PM의 선택 결과를 로드맵에 기록합니다. 사용자의 명시적 요청은 아래 기본값보다 우선하되 구현 가능성과 안전성을 확인한 뒤 적용합니다.

사용자가 별도 방식을 요청하지 않는 한 다음을 기본값으로 적용합니다.

- C# UI는 기존 WPF 비주얼 디자이너 흐름과 WPF 컨트롤, 스타일, 리소스를 사용합니다. 기본적으로 UI에서 컨트롤을 더블클릭하여 프로젝트의 기존 패턴에 맞는 코드 비하인드 이벤트 함수가 생성·연결되도록 제작합니다. XML/XAML 편집기를 직접 수정하는 방식은 기본 UI 제작 방식으로 사용하지 않으며, 프로젝트 관례나 사용자의 명시적 요청에 필요한 경우에만 생성된 마크업을 보완합니다. 기존 프로젝트가 MVVM/Command 바인딩을 기준으로 삼고 있으면 해당 관례를 유지하고, 기본 이벤트 연결 방식의 예외로 기록합니다.
- MFC UI는 `OnPaint`, `OnDraw` 또는 기존 커스텀 페인트 헬퍼와 같은 프로젝트의 DC(Device Context) 그리기 경로를 사용합니다. 새 시각 배치에는 리소스 에디터를 사용하지 않습니다. 호환성에 필요한 기존 리소스 ID, 문자열, 이미지, 컨트롤은 유지할 수 있지만 시각 배치와 렌더링은 DC 경로로 처리합니다.
- 플랫폼 또는 제작 방식의 예외는 사유, 영향받는 파일·구성요소, 유지보수·검증 영향을 기록합니다.

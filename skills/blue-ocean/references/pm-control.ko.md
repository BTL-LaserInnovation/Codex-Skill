# PM 업무 통제·예측·보고

업무 배정 또는 진척·잔여 작업·토큰·완료 시각 보고 전에 읽습니다. PM 직접 작업과 전문가가 지시한 타이핑 작업을 포함한 모든 subAgent에 적용합니다. 작은 작업은 같은 사실을 짧은 작업 기록에 남기며, 보고 양식을 채우려고 에이전트나 원장을 만들지 않습니다.

## PM 권한과 업무지시

- 승인된 범위와 사용자 한도 안에서 PM이 우선순위, 담당자, 의존성, 동시 실행 수, 보고 시점, 작업별 토큰 할당량을 정합니다. 근거를 요구하고 중복·정체·초과 작업의 일시 중지, 취소, 재배정, 재계획을 결정합니다. 완료 산출물을 보존하고 중요한 예측 변경을 설명합니다. 전문가의 지시와 중첩 에이전트도 추가 작업 전에 PM 계획에 취합하며 추적되지 않는 예산을 만들거나 계획을 우회하지 않습니다.
- 이 관리 권한으로 저장된 스킬 선택 권한을 바꾸거나, 새 유료 서비스를 사용하거나, 사용자 토큰 상한을 올리거나, 제품 범위를 넓히거나, 필수 QC·DR·구동 근거를 생략하거나, 명시적 중단을 무시하지 않습니다. 별도 결정 대기 중에도 독립적인 승인 작업은 계속하며 기존 권한 안의 일상적 일정 조정에 새 허락을 요구하지 않습니다.
- 배정 전에 작업 ID, 상위 작업, 지시자, 에이전트 ID·역할·실제 모델, 범위·제외 사항, 산출물, 의존성, 파일 담당, 인수 근거·책임자, 가중 마일스톤(검증·인수 포함), 예상 토큰, 잔여 시간·완료 예상 구간, 보고 주기·보고 상향 조건을 기록합니다. PM 통합·검토·QC 작업량도 계획에 포함합니다. 과거 비교 기록, 가정, 신뢰도를 식별합니다. 이 구체적인 지시를 작업자에게 전달하고 첫 보고 기회에 수신 확인 또는 추정 수정 의견을 받습니다.
- 최초 예상치, 현재 예측치, 작업 할당량을 구분합니다. 예상 범위의 상한까지 사용해도 된다는 뜻은 아닙니다. 할당량은 기존 프로젝트·사용자 한도 안에서 정하거나 PM 계획상 허용량임을 명시하며, 후자는 사용자 승인 쿼터로 표현하지 않습니다. 사용자 한도를 만들지 않습니다. 작업자는 계획 밖 확장이나 할당량 초과 전에 결과를 반환하고 PM이 다음 승인 작업을 결정합니다.

## 보고와 진척 근거

- 작업자는 수신 확인, 마일스톤 완료, 인계, 차단 발생, 중요한 예측 변경, 종료 시 보고합니다. 다중 에이전트 작업 중 기본 보고 목표는 60초이며 PM이 작업에 맞게 조정할 수 있습니다. 다음 도구·메시지 처리 가능 시점에 보고하며, 백그라운드 타이머나 클라이언트·도구 차단 중 실시간 갱신 보장이 아닙니다. 백분율을 받기 위해 정상적인 긴 작업을 중단하지 않습니다.
- 보고에는 작업·에이전트 ID, 시간대가 있는 보고 시각, 상태, 완료 마일스톤·근거, 현재 작업, 남은 산출물·검증, 진척률, 사용 토큰의 실측 여부·출처·집계 범위, 잔여 토큰 범위, 잔여 시간·완료 예상 구간, 차단·의존성, 신뢰도, 다음 행동·보고 시점을 포함합니다. 변화 없는 긴 실행은 마지막 관측 내용과 경과 시간을 보고합니다. 생존 신호는 진척 근거가 아닙니다.
- 진척률은 합계 1인 합의된 가중치와 근거가 있는 완료 마일스톤으로 계산합니다. 필수 통합·검증·인수에 0보다 큰 가중치를 둡니다. 경과 시간, 사용 토큰, 파일 수, 작업자의 “거의 완료” 표현으로 계산하지 않습니다. 구현 완료와 최종 인수를 구분하며 현재 필수 근거와 PM 인수가 있어야 작업 상태를 `complete`와 100%로 표시합니다.
- 전체 진척률은 작업별 진척률에 합의된 범위 가중치를 곱해 합산하며 최하위 산출물을 한 번만 셉니다. 상위 요약에 하위 작업량을 다시 더하지 않습니다. 예측 갱신으로 기준 가중치를 바꾸지 않으며 범위·가중치 변경이나 마일스톤 재개방으로 진척이 낮아지면 이력을 남깁니다. 실행 상태(`pending`, `running`, `verification_pending`, `needs_changes`, `blocked`, `complete`, `cancelled`)와 진척률을 별도로 표시합니다. 보고 지연은 `stale`이며 자동 실패·완료가 아닙니다.
- PM은 첫 보고 누락 시 갱신을 요청하고 실제 에이전트·도구 상태를 확인한 뒤 중단·재시작·재배정을 결정합니다. 차단, 이전 범위를 벗어난 예측, 할당량·사용자 상한 초과 우려, 의존성 변경, 인수 근거 누락은 즉시 PM에게 보고합니다. 응답을 받을 수 없으면 마지막 보고를 보존하고 최신성·완료 예상의 불확실성을 표시하며 독립 작업을 계속합니다. 최신 작업자 보고를 꾸며내지 않습니다.
- 필수 보고 필드도 알 수 없으면 `null`/`unknown`과 사유·다음 정보 수집 행동을 기록합니다. 인계받은 작업에 합의된 마일스톤 가중치나 완료 근거가 없으면 PM이 근거 있는 기준을 세우기 전까지 관측 상태와 진척률 산정 불가를 표시하며 표를 채우려고 백분율을 만들지 않습니다.

## 과거 작업 기반 토큰 추정과 보정

1. 배정 전에 기존 작업·이력에서 유사한 완료 작업을 찾습니다. 작업 유형, 산출물·작업 단위, 코드·문맥 크기, 재사용, 모델, 구현 복잡도, 의존성, 검증·보완 반복을 비교합니다. 동일 프로젝트를 우선하고 허용된 다른 프로젝트 요약을 사용하더라도 비공개 내용을 복사하지 않습니다. 기록 ID·경로, 표본 수, 실측 범위, 유사점·차이를 남깁니다. 이력이 없으면 낮은 신뢰도의 초기 추정으로 표시하며 과거 평균을 만들지 않습니다.
2. 비교 가능한 실행의 전체 실측 토큰을 우선합니다. 유사 작업 단위당 토큰 중앙값과 관측 편차를 기준으로 하한·상한을 추정하고, 문맥 로딩·낯선 코드·모델·추가 QC 등 차이를 기록해 보정합니다. 줄 수나 시간만으로 무관한 작업을 비교하지 않습니다. 표본이 적거나 차이가 크면 범위를 넓히고 신뢰도를 낮추며 판단으로 정한 범위를 설명합니다. 한 건은 유추 근거이지 신뢰할 통계 구간이 아닙니다. 실측 표본과 추정 표본을 구분하고 실측인 것처럼 섞지 않습니다.

   이력이 없으면 조사·문맥 로딩, 구현, 검증·인계로 구체적으로 나누고 확인된 작업 단위와 명시한 가정으로 개략 범위를 추정합니다. 판단 추정·낮은 신뢰도로 표시하고 첫 제한된 마일스톤 후 보정합니다. 이 근거조차 없으면 해당 예측을 미정으로 남기고 사유·다음 제한된 조사를 명시하며 임의의 정밀한 숫자를 채우지 않습니다. 과거의 “검증 완료”에 무엇이 포함되었는지 확인한 뒤 QC·PM 비용을 더하여 이전 검증을 중복 계산하지 않습니다.
3. 중복 없는 비용 담당별로 PM 계획·조율, 각 작업자(입력·문맥 포함), 통합, QC, 예상 보완, 명시적 프로젝트 예비량을 추정합니다. 상위 합계는 하위 비용의 취합이며 상위 요약을 중복 계산하지 않습니다. 제공자의 상위 세션 합계에 하위 사용량이 포함되면 다시 더하지 않습니다. 입력·출력·캐시 입력·추론 포함 여부를 명시합니다. 캐시 입력은 입력의 부분집합, 추론은 출력의 부분집합일 수 있으므로 관측된 제공자 집계 기준에 따라 한 번만 세고 원본 카운터를 보존합니다. 토큰으로 금액을 단정하거나 시간을 실제 토큰으로 변환하지 않습니다.
4. 도구·세션·제공자 카운터로 노출된 경우에만 실측 토큰으로 기록하고 시각·출처·범위(에이전트·작업·세션, 누적·증분)를 남깁니다. 동일 계측 구간에만 증분을 적용하고 이전 시도·재시도 비용을 유지하며 카운터 초기화·계측 공백을 기록합니다. 사용량 미제공은 `null`/`unavailable`이며 0이 아닙니다. 실측과 추정 사용량을 분리합니다. 부분 계측이면 실측 소계와 누락 범위를 표시하고 전체 실측 합계로 부르지 않습니다. 숨은 문맥·토큰 잔액·상한 강제 집행·실시간 과금이 관측된다고 주장하지 않습니다.
5. 남은 작업과 비교 근거로 잔여 토큰을 갱신하며 소모량을 진척으로 보지 않습니다. 중복 없는 완전 계측 시 `최종 예측 = 실측 사용량 + 잔여 예상량`입니다. 그 외에는 실측 소계, 계측되지 않은 사용량의 추정치, 잔여 예상량을 나누고 합계를 예측치로 표시합니다. 최초 예상과 모든 수정의 시각·사유를 보존합니다. 예비량은 별도 관리하며 위험이 해소될 때만 해제하고 작업과 예비량에 이중 반영하지 않습니다. 할당량·사용자 상한에 접근하거나 초과할 전망이면 다음 재량 작업 배정 전에 PM이 결정합니다. 사용량 미확인으로 상한 준수를 입증할 수 없으면 그 한계를 보고하고 해당 재량 배정을 중단합니다.
6. 실패·취소를 포함한 종료 시 최초·최종 예상, 실측 또는 명시적 미제공, 모델, 실제 작업 단위, 문맥·재사용 특성, 검증·보완 횟수, 실제 작업·대기 시간, 결과, 예상 오차·사유를 보존합니다. 집계 범위가 일치하는 실측에만 최초·최종 예상 중간값 대비 비율을 계산합니다. 다음 추정은 유사 완료 기록으로 보정하며 실패·취소 비용은 성공 단위 기준 대신 위험·재작업 근거로 남깁니다. 과거 관측을 나중 추정으로 덮어쓰지 않습니다.

## 남은 시간과 프로젝트 완료 예상

- 유사 작업 시간과 관측 마일스톤으로 남은 실제 작업·검증 시간을 범위·신뢰도와 함께 추정합니다. 의존성·에이전트 슬롯·빌드·사용자 결정·환경 대기는 별도로 기록합니다. 고정 토큰/분 환산이나 경과 시간/진척률의 선형 외삽을 완료 약속으로 쓰지 않습니다.
- 실제 슬롯, 같은 파일의 순차 편집, 통합, QC, 보완 여유를 반영하여 남은 의존 경로의 완료 구간을 계산합니다. 순차 단계는 더하고 독립 단계도 자원이 허용될 때만 겹칩니다. 전체 시간은 모든 작업자 시간의 합이나 가장 빠른 작업자 ETA가 아닙니다.
- 예: “잔여 20~35분, 완료 예상 15:20~15:35 Asia/Seoul”과 관측 시각·가정을 함께 표시하며 사용자 시간대를 사용합니다. 종료를 모르는 외부 대기는 “완료 시각 미정, 의존성 X 해소 후 실제 작업 20~35분”과 다음 확인 시점을 표시합니다. 오래되거나 중단된 실행은 새 보고·상태 조정 후 예측을 재사용합니다. 턴 종료 후에도 감시한다고 주장하지 않습니다.

## 지속 기록과 사용자 보고

기존 로드맵·작업 기록을 재사용합니다. 다단계·세션 간 작업에 동등한 기록이 없으면 [작업 기록 템플릿](../templates/pm-task-record.json)을 `cfg/blue-ocean.harness/pm/tasks/<task-id>.json`에 맞춰 사용합니다. PM이 유지하는 보고 계약이며 새 실행 명령이나 자동 강제되는 스키마가 아닙니다. 검증·인수 상태의 원본은 계속 하네스 `state.json`이며 연결하고 불일치는 보고 전에 조정합니다. PM 한 명이 보고를 순차 저장하고 임시 파일 교체·재읽기로 확인하며 이전 보고·수정·종료 기록을 보존합니다. 작업자는 공유 기록 동시 편집 대신 갱신을 전달합니다. 기존 데이터가 잘못되면 보존·조정하고 초기화하지 않습니다. 공용 스킬 업데이트에도 프로젝트 기록을 유지하고 재사용 템플릿에 실제 프로젝트 이력을 넣거나 로컬 로그를 기본 커밋하지 않습니다.

PM은 배정, 의미 있는 중간 시점, 상태 요청, 종료 시 아래의 간결한 한글 현황을 제공합니다.

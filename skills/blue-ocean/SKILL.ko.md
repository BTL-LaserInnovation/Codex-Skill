# 블루오션

기존 프로젝트 관례와 코드를 활용하여 승인된 목표를 완수합니다. 별도 요청이 없으면 계획·진행·결과는 한글로 작성하고 코드·식별자는 유지합니다.

## 시작과 공통 제약

- 실행 초기에 [업데이트와 권한](references/update-and-authority.ko.md)에 따라 지정 원격 소스를 한 번 확인하고, 로컬 기능을 보존하며 허용된 업데이트만 적용합니다.
- 지원 스킬 선택 전에 `<ProjectRoot>/cfg/blue-ocean.preferences.json`을 읽고 저장된 권한과 스킬별 결정을 따릅니다. 저장되거나 명시된 선택이 없으면 의존 작업 전에 선택을 받습니다.
- 프로젝트 분석·구현에는 설치된 `project-symbol-guide`를 지속 허용에 따라 적극 사용하고, 이후 사용자 제한과 [심볼 가이드 절차](references/implementation.ko.md#프로젝트-심볼-가이드)를 따릅니다. 다른 스킬 사용이나 새 프로젝트 함수 생성까지 허용하는 것은 아닙니다.
- 계획 전에 관련 프로젝트 로컬 규칙을 읽습니다. 규칙과 보조 자료는 `<ProjectRoot>/localrule/` 아래에 두고, 지속 지시·반복 교정·이전은 [로컬 스킬 절차](localrule/local-skills.md)를 따릅니다. 공용 스킬 업데이트 시 프로젝트 규칙을 보존합니다.
- 블루오션의 PM만 **GPT-6.1 Sol** (`gpt-6.1-sol`), 나머지 모든 에이전트는 **GPT-6.1 Terra** (`gpt-6.1-terra`)를 사용합니다. 에이전트 생성이나 큰 병렬 작업 전에 [에이전트와 자원](references/agents-and-resources.ko.md)을 적용하며 모델을 임의 대체하지 않습니다.
- UI 변경은 작은 수정도 구현 전에 시안을 제시하고 명시적 사용자 컨펌을 받습니다. [UI 컨펌 절차](references/gui-workflow.ko.md#구현-전-ui-시안과-사용자-컨펌)를 따르며 PM 승인으로 사용자 컨펌을 대신하지 않습니다.
- 불필요한 작업 생략, 프로젝트 기존 코드, 언어 표준 라이브러리, 플랫폼 기본 기능, 설치된 의존성, 최소 구현 순으로 충분한 첫 해법을 선택합니다. 필수 검증·오류/데이터 손실 처리·보안·접근성·관측성·테스트를 보존합니다.

## 해당 작업의 문서 선택

해당 결정 전에 필요한 절만 읽습니다. 요구사항이 확정된 통상 수정은 짧은 작업 기록과 영향 검증으로 진행하며 무관한 역할·전체 저장소 조사·새 원장은 필요하지 않습니다. 해당 디자인 리뷰(DR), Debug 실제 구동, Computer Use 확인, 독립 인수 조건은 유지합니다. 참조 문서의 명령·템플릿 경로는 설치된 스킬 루트를 기준으로 합니다.

| 현재 작업 | 읽고 적용할 문서 |
| --- | --- |

| 업무지시·진척·토큰 예상·완료 예측 | [PM 관리](references/pm-control.ko.md): 보고, 과거 보정, 할당량, 의존성을 반영한 완료 구간. |

## 완료

개발자는 영향받는 프로젝트 고유 검증을 수행하고, QC는 기대/실제 결과를 기록하여 보완 후 재검증합니다. 불가·거절된 검증은 차단/미실행으로 남깁니다. PM은 현재 필수 근거나 권한 있는 문서화된 예외를 확인한 뒤 인수하고 제공 범위·변경 파일·검증·남은 제약을 보고합니다.

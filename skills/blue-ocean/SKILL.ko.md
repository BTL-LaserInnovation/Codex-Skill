# 블루오션

이 스킬은 명확한 멀티 에이전트 개발 절차가 필요한 소프트웨어 개발 작업에 사용합니다. C++, C# 및 사용자가 요청한 다른 플랫폼을 지원하며, 특정 프레임워크를 강제하거나 사용자의 제품 요구사항을 변경하지 않습니다.

## 역할과 책임

실질적인 작업을 시작하기 전에 다음 역할을 정합니다.

- **프로젝트 매니저(PM):** 요청 결과, 범위, 완료 기준을 명확히 하고 진행 방향을 결정합니다. 로드맵을 승인하고 업무를 배정하며 최종 결과를 보고합니다.
- **시스템 설계자:** PM 방향을 아키텍처, 인터페이스, 의존성, 마일스톤, 위험 요소, 검증 전략을 포함한 실행 가능한 로드맵으로 전환합니다. 승인된 스킬 카탈로그 또는 로컬에서 사용할 수 있는 스킬을 검색해 작업에 필요한 역량을 찾고, 최소한의 적합한 스킬을 선정하여 GUI 디자이너와 소프트웨어 개발자에게 배정합니다. 구현이 로드맵과 일치하는지 추적합니다.
- **GUI 디자이너:** 사용자 흐름, 화면 레이아웃, 컴포넌트 상태, 시각적 위계, 상호작용 규칙을 정의합니다. 시스템 설계와 일관된 구현용 인수인계 자료를 만들고, 구현에 영향을 주는 사용성·접근성 요구사항을 기록합니다.
- **소프트웨어 개발자:** 요청된 언어로 승인된 작업을 구현하고, 완료 내용·테스트·차단 요소를 보고합니다.
- **프로그램 검토 및 검증 QC:** 로드맵과 완료 기준을 기준으로 변경을 독립적으로 검토하고, 작업 규모에 맞는 검증을 수행하거나 요청합니다. 결함과 출시 위험을 기록합니다.

각 역할에 한 명의 책임 에이전트를 배정합니다. 자원이 부족할 때만 한 에이전트가 여러 역할을 겸할 수 있으며, 가능한 한 QC의 독립성을 유지합니다.

## 운영 절차

1. PM은 요청을 간결한 목표, 제약, 완료 기준, 언어/플랫폼 결정으로 정리합니다. 구현 전에 범위에 중대한 영향을 주는 누락된 결정을 확인합니다.
2. 시스템 설계자는 산출물, 순서, 담당자, 의존성, 기술 결정, 위험 요소, 검증 시점을 포함한 로드맵을 작성합니다. 전문 작업별로 승인된 스킬 카탈로그 또는 로컬 스킬을 검색하고, 선정한 스킬·대상 사용자·목적·사전 조건을 기록한 뒤 필요한 경우 GUI 디자이너 또는 소프트웨어 개발자에게 배정합니다. 사용자 대상 기능은 관련 구현을 배정하기 전에 GUI 디자이너가 사용자 흐름과 화면/디자인 인수인계를 제공합니다. 프로젝트에 지속 파일이 있으면 이 자료를 프로젝트 산출물에 보관하고, 그렇지 않으면 작업 응답에 제시합니다.
3. PM은 로드맵을 검토하고 범위 충돌을 해결하며 승인된 작업을 각 에이전트에게 배정합니다. 유용해 보인다는 이유만으로 범위 밖 구현을 시작하지 않습니다.
4. 개발자는 배정된 항목을 구현하고 관련 빌드, 테스트, 검사를 실행합니다. GUI 작업에서는 승인된 디자인 인수인계를 사용하고, 구현 가능성 문제나 디자인 차이가 있으면 임의 변경하지 말고 즉시 보고합니다.
5. 시스템 설계자는 의미 있는 마일스톤마다 로드맵 정합성을 확인합니다. GUI 디자이너는 구현 화면이 승인된 상호작용 및 시각 요구사항과 일치하는지 검토합니다. QC는 중간 결과와 최종 변경 모두를 검토하고, 심각도와 재현 가능한 근거를 갖춘 결과를 기록하여 결함을 담당자에게 전달합니다.
6. 검증된 결함을 해결하고 수정 영향 범위에 해당하는 검사만 다시 실행한 뒤, 원래 완료 기준에 대해 PM 승인을 받습니다.
7. PM은 제공 범위, 변경 파일 또는 구성요소, 수행한 검증과 결과, 남은 위험 또는 후속 작업, 의도적인 차이를 포함한 최종 보고서를 작성합니다.

## 협업 규칙

- 독립적인 작업에만 병렬 작업을 사용합니다. 아키텍처 결정과 공유 파일 편집은 충돌을 피하도록 순차적으로 진행합니다.
- 승인된 로드맵을 기준 문서로 취급합니다. PM이 중요한 범위, 설계, 일정 변경을 승인하면 로드맵을 갱신합니다.
- 시스템 설계자는 이미 사용할 수 있고 프로젝트와 관련된 스킬을 GUI 디자이너 또는 소프트웨어 개발자에게 배정할 수 있습니다. 배정은 지정된 작업에서 스킬을 사용할 권한만 부여하며, 외부 서비스 접근, 새 자격 증명, 의존성 설치 권한을 부여하지 않습니다.
- 적합한 승인 스킬이 없으면 시스템 설계자는 부족한 역량을 보고하고 PM에게 스킬 또는 스킬 생성 작업을 제안합니다. 스킬 설치, 외부 서비스 연결, 중요한 의존성 도입 전에는 PM/사용자 승인을 받습니다.
- QC가 스킬 제약 준수 여부를 확인할 수 있도록, 대상 역할과 목적을 포함한 스킬 배정을 로드맵에 기록합니다.
- 승인된 GUI 인수인계를 화면과 상호작용의 기준 문서로 취급합니다. 사용자 흐름, 레이아웃, 컴포넌트 동작, 접근성에 영향을 주는 변경은 GUI 디자이너 검토가 필요하며 범위가 변경되면 PM 승인도 받습니다.
- C++과 C#에서는 프로젝트에 이미 있는 빌드·테스트 명령을 우선 사용합니다. 사용자 승인 없이 새 빌드 시스템이나 의존성을 도입하지 않습니다.
- QC는 검증된 결함과 제안을 구분해야 합니다. 출시 차단 결함에는 근거, 기대 결과와 실제 결과, 명확한 담당자가 필요합니다.
- 필요한 결정, 자격 증명, 외부 서비스, 완료 기준을 확보할 수 없으면 시스템 설계자/PM 또는 사용자에게 계속 진행하기 위해 필요한 최소한의 결정을 보고합니다.

# Mocha 라이브러리 참조

MFC 또는 C++ 작업에서 요청 기능이 로컬 Mocha 라이브러리에 이미 있을 수 있으면 이 스킬을 사용합니다. 새 코드, 컨트롤, 유틸리티, 의존성을 추가하기 전에 Mocha를 근거 기반 재사용 대상으로 다룹니다.

## 라이브러리 경로 확인

1. 현재 환경에서 `PathMocha`를 읽고, 없으면 User 및 Machine 환경 변수 범위를 차례로 조회합니다.
2. 확인된 경로에 `include`, `src`, `all.sln`이 있는지 검사합니다. 일반 참조 작업에서 환경 변수를 설정하거나 변경하거나 영구 저장하지 않습니다.
3. 경로를 찾을 수 없으면 Mocha를 탐색하지 못했음을 보고하고 대상 프로젝트의 일반 재사용 우선 절차를 계속합니다. 고정 경로가 존재한다고 가정하지 않습니다.

## 빠른 탐색

넓은 탐색 전에 [생성된 색인](references/mocha-library.index.json)을 읽습니다. 색인은 Mocha 솔루션, 공용 헤더 그룹, Visual C++ 프로젝트, 프로젝트 참조, 사용 가능한 라이브러리를 기계적으로 찾을 수 있게 합니다. 관련 하위 시스템을 판단할 때는 [Mermaid 다이어그램](references/mocha-library.mmd)을 읽습니다.

Mocha 모듈, 공개 API, 의존성이 의미 있게 바뀌면 이 스킬 디렉터리에서 `scripts/update-mocha-index.ps1`를 실행해 두 산출물을 갱신합니다.

생성기는 실행 시 `PathMocha`를 해석하며 Mocha 체크아웃을 변경하지 않습니다. 색인은 로컬 라이브러리 구조의 배포용 스냅샷이므로 커밋 전에 갱신 결과를 검토합니다.

## 재사용 우선 탐색

MFC/C++ 기능을 설계하거나 구현하기 전에 도메인 용어, 의도한 클래스/API 이름, 유사한 컨트롤 또는 동작을 관련 Mocha 범위에서 탐색합니다.

- 먼저 `<PathMocha>/include`의 공개 계약을 탐색하고, 일치하는 `<PathMocha>/src` 구현과 `.vcxproj`를 확인합니다.
- 헤더, 소스, 프로젝트 파일에 한정한 `rg` 검색을 사용합니다. 넓은 트리를 나열하기 전에 색인에서 찾은 관련 모듈부터 탐색합니다.
- 후보의 공개 헤더, 소유권/수명, 해당 시 MFC 메시지 또는 UI 동작, 소스/빌드 프로젝트, Debug/Release x64 호환성을 확인합니다.
- 통합을 제안하기 전에 후보 프로젝트의 include 경로, 라이브러리 경로, 종속 라이브러리, 전처리기 정의를 확인합니다. 소비 프로젝트의 기존 빌드 규칙을 보존합니다.
- 요구 사항을 만족하는 기존 공개 API, 라이브러리, 컨트롤, 구현 패턴을 재사용합니다. 접근하기 쉽다는 이유만으로 구현을 새 유틸리티에 복사하거나 동등한 컨트롤을 만들지 않습니다.

적합한 후보가 없으면 검색어와 제외한 후보를 짧게 기록한 다음 가장 작은 호환 구현을 작성합니다. 공개 계약, 소유권 모델, 플랫폼/구성 지원, 라이선스 또는 의존성이 대상 프로젝트와 충돌하면 후보는 적합하지 않습니다.

## 경계

Mocha 체크아웃은 공유 참조 및 의존성 원본으로 다룹니다. 사용자가 Mocha 자체 변경을 명시적으로 요청하지 않는 한 소스, 바이너리 라이브러리, 프로젝트 파일, 환경 설정 스크립트를 수정하지 않습니다. 후보를 사용하기 위해 새 의존성을 추가하거나 대상 프로젝트의 환경 변수를 바꾸지 않으며, 먼저 통합 영향을 제시합니다.

관찰된 저장소 구조와 빌드 세부 사항은 [Mocha 레이아웃 참고](references/mocha-layout.ko.md)를 읽습니다.
